# Stage 4 — Sol-eid Writer/Recruiter Mirror

## Modell og fysisk grense

- Én manuelt startet chat per Stage 3-miniklynge, normalt omtrent 10 jobber.
- Modell: **GPT-5.6 Sol, Extra High**; bruk Max selektivt for omfattende
  omskriving, konkurrerende vinkler eller krevende offentlig/regulert språk.
- Jobb kun i `stg4_mirror/`; skriv bare til aktuell miniklynge i `output/`.

## Tillatt input

- Stage 3-kumulativ input med `job_identity.json`, låst evidensbase/blueprint,
  `draft_package.json`, relevant vacancy og analyse;
- `PACKAGE_CONTRACT.md`, kalibrering og Stage 4-/felles runtimekjerne;
- kandidatmyndighet kun for kontroll av ett konkret faktum.

## Én prompt, to interne faser

Arbeid i 5+5-bølger, én jobb helt ferdig før neste: **Wave 1** er de første
fem jobbene, midpoint kommer etter Wave 1, og **Wave 2** er resten.

1. **Phase A:** les vacancy, analyse, blueprint og draft på nytt. Rediger for
   første-20-sekunders klarhet, arbeidsgiverspesifisitet, begripelig verdi,
   jeg/vi, Bokmål-rytme og kanalkomplementaritet.
2. **Midpoint/checkpoint:** lagre en komplett foreløpig `final_package.json`
   og kontroller schema, identitet, baseline, portalgrenser og at Stage 4 ikke
   innfører ny employment-ID.
3. **Phase B — source-first self-audit:** les valgt evidens og relevant
   vacancytekst på nytt. Reparer undersalg, oversalg, generisk prosa,
   teknisk overlast og repetisjon direkte; kontroller employer-swap og
   variasjon mot tidligere jobber i miniklyngen.

## Autoritative output per jobb

Skriv kumulative artefakter til `output/<mini_cluster_id>/<job_id>/` og legg
til:

- `final_package.json` med `source_stage: "STAGE4_FINAL"`;
- privat `review_flags.md` med headingene `# Must verify`,
  `# Strong but defensible` og `# Optional polish`; flagg skal være konkrete,
  lokaliserte og uten PASS/REVISE/BLOCK-dom;
- `_DONE.md`:

```text
Stage: 4
Status: COMPLETED
Artifact: final_package.json; review_flags.md; job_identity.json
Job: <job_id>
Model: GPT-5.6 Sol
Effort: xhigh
```

- oppdatert `BATCH_STATUS.md` i fullt Wave 1/midpoint/Wave 2-format fra
  `START_HERE.md`.

## Non-veto, blocking og recovery

Mirror er en konstruktiv editor, ikke en semantic gatekeeper. Ikke returner
PASS, REVISE, BLOCK, GO eller NO-GO som pakkedom. Bare reell mekanisk
unusability gir `BLOCKED.md`. En aktiv blocker, manglende final source eller
manglende `_DONE.md` stopper finalisering av akkurat den jobben, ikke andre.

Ved continuation gjenbrukes bare komplette Stage 4-jobber med finalpakke,
reviewfil og gjeldende `_DONE.md`. Ikke render, send, publiser, forsk på
arbeidsgiver, kall API eller utfør neste steg.
