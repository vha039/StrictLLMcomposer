# Jobbsøk_26 P0.7 — start her

P0.7 er en manuelt startet, fysisk isolert firestage-flyt. Den produserer
norske jobbsøkingspakker, men sender aldri inn, publiserer aldri og kontakter
aldri en arbeidsgiver. Modellene arbeider bare i manuelle Work-chatter;
scriptne validerer, flytter og renderer filer.

## 1. Installer og preflight

Målmiljø: Windows, Python 3.11 eller 3.12, PowerShell 7+ og LibreOffice med
soffice i PATH (eller oppgitt eksplisitt). Den operative modellruten står i
MODEL_ROUTING.md.

~~~powershell
Set-Location C:\Codex\Jobbsok_26_P0.7
if (-not (Test-Path .\.venv)) { python -m venv .venv }
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m unittest discover -s tests -p "test_*.py" -v
~~~

Kontroller kandidat- og masterhashene før produksjon:

~~~powershell
Get-FileHash context\Work_experience.md, context\Education.md, context\Other_high_value_information.md, context\templates\CV_MASTER.docx, context\templates\APPLICATION_MASTER.docx -Algorithm SHA256
~~~

Bare disse tre scriptne er aktive:

~~~text
scripts/ingest.py
scripts/advance.ps1
scripts/finalize.py
~~~

## 2. Topologi, ID-er og modellruting

Målbatchen er to XL-makroklynger à omtrent 20 jobber, som splittes i to
miniklynger à omtrent 10 jobber hver. Normalflyten er 12 chatter/prompter:

| Stage | Klynger/chatter | Interne bølger | Modell |
|---|---:|---|---|
| 1 | 2 makro | 10+10 | Terra Max |
| 2 | 2 makro | 10+10 | Sol Max |
| 3 | 4 mini | 5+5 | Terra Extra High, selektivt Max |
| 4 | 4 mini | 5+5 | Sol Extra High, selektivt Max |

Eksempel-ID-er:

~~~text
batch:        B01
makroklynge:  B01_C01_process_digitalization
jobb:         B01_J003_unil_project_manager
miniklynge:   B01_C01A_process_digitalization
~~~

Maskin-ID-er er ASCII små bokstaver, tall og _. batch_id må være likt i jobb,
makroklynge, miniklynge, job_identity.json og package.

## 3. Klargjør Stage 1-input og ingest

Opprett én mappe per godkjent jobb:

~~~text
stg1_analyze/input/<macro_cluster_id>/<job_id>/
  vacancy.pdf                 # eller en meningsfull vacancy.md
  vacancy.md                  # valgfri før ingest
  notes.md                    # valgfri
~~~

ingest.py krever meningsfull Markdown eller én PDF kalt vacancy.pdf. Den
godtar en legitim kort enkeltside med varsel, men blokkerer samlet uleselig
eller dominert skannet input. Exit-kode 0 betyr komplett, 1 betyr minst én
jobbblocker og 2 betyr konfigurasjons-/ID-feil.

~~~powershell
python scripts\ingest.py stg1_analyze\input
python scripts\ingest.py stg1_analyze\input --force
~~~

Bruk --force bare for bevisst erstatning av eksisterende vacancy.md fra en
kontrollert vacancy.pdf.

### notes.md-mal

~~~markdown
# Operator notes

Letter required: AUTO
Language: nb-NO

## Portal questions

- question_id:
  question:
  max_words:
  max_chars:

## Must emphasize

## Must handle carefully

## Other
~~~

Notater kan styre kanal, harde grenser og oppmerksomhet, men er aldri
kandidatmyndighet.

## 4. Stage 1 — kandidatblind analyse

Start en ny ChatGPT Work-chat i stg1_analyze/ per makroklynge. Velg Terra Max:

~~~text
Prosesser bare makroklyngen input/<macro_cluster_id>/ i denne Stage 1-chatten.
Følg AGENTS.md: kandidatblind, alfabetisk rekkefølge, interne 10+10-bølger og
Phase A → midpoint/checkpoint → Phase B source-first self-audit i samme chat.

For hver komplette jobb skal output inneholde job_identity.json,
vacancy_analysis.md og Stage 1 _DONE.md. Oppdater BATCH_STATUS.md etter hver
jobb. Skriv BLOCKED.md bare ved mekanisk unusability og fortsett med andre
uavhengige jobber. Ikke les kandidatfiler og ikke gjør Stage 2.
~~~

Kopier bare komplett Stage 1-output til tom Stage 2-input:

~~~powershell
Copy-Item stg1_analyze\output\B01_C01_process_digitalization stg2_strategy\input\ -Recurse
~~~

## 5. Stage 2 — evidensbase og package blueprints

Start en ny Work-chat i stg2_strategy/ per makroklynge. Velg Sol Max:

~~~text
Prosesser bare input/<macro_cluster_id>/ i denne Stage 2-chatten og følg
AGENTS.md. Arbeid i interne 10+10-bølger. Først bygges en shared,
source-first CLUSTER_EVIDENCE_BASE.md med to evidence lanes og én korrekt
MINICLUSTER_SPLIT.json. Deretter produseres én individuelt forankret
package_blueprint.md per jobb.

Bruk Phase A → midpoint/checkpoint → Phase B source-first self-audit i samme
chat. Bevar job_identity.json, oppdater BATCH_STATUS.md og skriv Stage 2
_DONE.md per jobb. Lås evidensbasen, splitten og blueprintene. Ikke skriv
employer-facing prosa eller gjør Stage 3.
~~~

Split en komplett makroklynge. advance.ps1 krever clusterbase, split,
BATCH_STATUS.md, job_identity.json, vacancy, analyse, blueprint, _DONE og
fravær av aktive blockere. Den kopierer aldri videre state-markører.

~~~powershell
.\scripts\advance.ps1 -Cluster B01_C01_process_digitalization
~~~

## 6. Stage 3 — norsk drafting

Start en ny Work-chat i stg3_write/ per miniklynge. Velg Terra Extra High;
eskaler selektivt til Max etter MODEL_ROUTING.md.

~~~text
Prosesser bare input/<mini_cluster_id>/ i denne Stage 3-chatten og følg
AGENTS.md. Arbeid i interne 5+5-bølger. For hver jobb: bygg draft_package.json
fra låst blueprint og evidence base, lag bare dynamiske CV-overstyringer mot
CV_BASELINE.md, og skriv naturlig Bokmål.

Utfør Phase A → midpoint/checkpoint → Phase B source-first self-audit i samme
chat. Valider schema, job_identity, baseline, ID-er, portalgrenser og intern
metadata-lekkasje. Skriv Stage 3 _DONE.md og BATCH_STATUS.md. Ikke render
dokumenter eller gjør Stage 4.
~~~

Kopier komplett miniklynge til en tom Stage 4-input:

~~~powershell
Copy-Item stg3_write\output\B01_C01A_process_digitalization stg4_mirror\input\ -Recurse
~~~

## 7. Stage 4 — Writer/Recruiter Mirror

Start en ny Work-chat i stg4_mirror/ per miniklynge. Velg Sol Extra High og
bruk Max selektivt ved behov:

~~~text
Prosesser bare input/<mini_cluster_id>/ i denne Stage 4-chatten og følg
AGENTS.md. Arbeid i interne 5+5-bølger. Rediger draft_package.json
konstruktivt til final_package.json; mirror er ikke en semantic gatekeeper.

Utfør Phase A → midpoint/checkpoint → Phase B source-first self-audit i samme
chat. Kontroller employer-swap, norsk rytme, jeg/vi, kanalroller og
no-new-facts. Skriv konkrete private review_flags.md under de tre obligatoriske
headingene, Stage 4 _DONE.md og BATCH_STATUS.md. Ikke render, send eller
publiser.
~~~

## 8. Check-only og rendering/finalisering

stg4_mirror/input er forventet jobbmengde. stg4_mirror/output er faktisk
ferdigstilt mengde. Finalizer gir aldri global PASS hvis én forventet jobb
mangler package, identitetsanker, Stage 4-_DONE.md, reviewfil eller er blocket.

~~~powershell
python scripts\finalize.py stg4_mirror\input stg4_mirror\output output --check-only
python scripts\finalize.py stg4_mirror\input stg4_mirror\output output
python scripts\finalize.py stg4_mirror\input stg4_mirror\output output --force
~~~

Finalizer renderer fra de originale Word-masterne, har LibreOffice-timeout,
kombinerer dynamiske CV-overstyringer med verifisert baseline, krever CV ≤2
A4-sider og søknad ≤1 A4-side, og lager bare per-jobb output. Den skriver
ikke FINALIZE_REPORT.md eller output/INDEX.md.

Gjør alltid manuell semantisk sluttgodkjenning før innsending. Private
review_flags.md skal aldri deles med arbeidsgiver.

## 9. Recovery og status

Hver stage bruker BATCH_STATUS.md, _DONE.md og BLOCKED.md. Fortsett i en ny
chat med denne teksten (juster stage/klynge):

~~~text
Fortsett bare denne stagen for <cluster_id>. Les BATCH_STATUS.md og gjeldende
output. Bevar bare jobber som både har dette stegets autoritative artefakter
og gyldig _DONE.md. Fullfør manglende eller ufullstendige jobber i samme
Phase A → midpoint/checkpoint → Phase B-prosess, oppdater status etter hver
jobb, og fortsett rundt jobbspesifikke mekaniske blockere. Skriv bare til
denne stages output og ikke start neste stage.
~~~

Statusmal:

~~~markdown
# <cluster_id> — Stage <n>

Model: <model>
Effort: <effort>
Target jobs: <count>

## Wave 1

### Completed
- <job_id>

### Current
- <job_id>

### Remaining
- <job_id>

### Blocked
- <job_id> — <kort mekanisk grunn>

## Midpoint review
- evidence pairs already used:
- candidate identities already used:
- repeated opening risks:
- jobs requiring escalation:

## Wave 2

### Completed
- <job_id>

### Current
- <job_id>

### Remaining
- <job_id>

### Blocked
- <job_id> — <kort mekanisk grunn>
~~~

Blockermal:

~~~markdown
# BLOCKED

Stage: <1|2|3|4>
Job: <job_id>
Reason: <konkret mekanisk unusability>
Required action: <eksakt operatorhandling>
~~~

## 10. Makroklyngegate og pilotlogg

Fullfør Gate A (ingest), alle stageartefakter, advance, --check-only og
rendering for én makroklynge før neste startes. Ikke kjør en kostbar 20-jobbs
pilot automatisk. Etter godkjente pakker, loggfør bare uttrykkelige Vegard-
korrigeringer i context/PERSUASION_CALIBRATION.md og én rad per relevant pilot
i docs/HYBRID_PILOT_LOG.csv.
