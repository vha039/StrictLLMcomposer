Beste fit-miljø:

- uklart eller underdefinert problem;
- fragmentert/svakt datagrunnlag;
- høy konsekvens av feil;
- behov for sporbar logikk og validering;
- løsningen må forstås, brukes, vedlikeholdes og overleveres.

## 4. KI-støttet arbeidskompetanse

### 4.1 Forsvarlig posisjonering

The strongest conclusion is not `advanced prompt user`. Vegard combines domain expertise, analytical judgment, technical implementation, structured context, bounded delegation, validation and governance into a repeatable **human-governed AI-enabled delivery workflow**. Current responsible-AI terminology supports emphasizing traceability, explicit human accountability and the ability to intervene or override; it does not strengthen the underlying experience claim.

`IDENTITY-AI` is subordinate to the selected route unless responsible AI-enabled delivery is itself a decisive vacancy criterion and the narrow `ROLE-AI-01` ceiling is respected.

Preferred labels:

- AI-assisted analysis and development;
- human-in-the-loop workflow design;
- human review, intervention and override points;
- coding-agent facilitation/orchestration;
- context and instruction design;
- AI-output validation and quality assurance;
- risk-aware automation;
- responsible GenAI adoption in analytical/technical work.

`Prompt engineering` is a useful search term but normally understates the capability and should be subordinate.

### 4.2 Repeterbar KI-arbeidsmodell

1. Clarify the decision/operational problem.
2. Assemble and structure relevant context.
3. Define source precedence, assumptions, constraints and prohibited shortcuts.
4. Decompose work into inspectable stages/artifacts.
5. Delegate bounded analysis, implementation, review or documentation.
6. Require tests, reconciliation, citations, proof or explicit uncertainty.
7. Review exceptions, stale state, logic drift and unresolved risk.
8. Translate output into a stakeholder-appropriate deliverable.
9. Preserve handoff context for the next human/agent.
10. Stop when mandatory coverage and quality thresholds pass.

For high-impact or externally consequential actions, preserve a human decision point and an auditable handoff. This is a workflow principle, not evidence of a formal enterprise AI-governance role.

### 4.3 Konkret evidens

The active forecasting workspace demonstrates a persistent operating structure for coding agents:

- project instructions defining scope, constraints, proof requirements and prohibited actions;
- separation among agent-operation files, source repository and generated dependencies;
- truth precedence prioritizing current files/tests over narrative memory;
- run initialization, compact patch logging and finish-state recording;
- run state, process logs, issue register, archives, handoffs and plans;
- helper tooling and targeted tests for handoff;
- domain invariants, including horizon-safe training and prohibition of silent feature drops;
- separation of local/synthetic validation from unvalidated live-database/model execution;
- non-destructive repository constraints.

The defensible ownership claim concerns architecture, orchestration, automated components, integration, review, validation and human accountability. Implementation is distributed among Vegard, coworker and AI/coding agents.

### 4.4 Trygge KI-påstander

- Designs structured human-governed AI workflows with explicit scope, source hierarchy, constraints, stages, artifacts, acceptance criteria and stopping rules.
- Uses generative AI/coding agents for complex analysis, repository work, documentation, review and implementation support while retaining human accountability.

### 6.1 Systemtenkning og kompleksitetsreduksjon

- incorrect grain;
- leakage;
- target ambiguity;

### 6.3 Oversettelse mellom virksomhet og teknologi

Moves between management questions, healthcare operations, economic logic, data models and code. Differentiating for bridge roles where technical solutions must remain operationally and economically meaningful.

### 6.4 Selvstendig teknisk problemløsning

### 6.5 Kvalitetsbevisst pragmatisme

Values robust/maintainable solutions but does not equate novelty or complexity with value. Preserves validated behaviour when aggressive modernization would create risk; prioritizes correct validation/feature semantics over superficial model sophistication.

### 6.6 Kommunikasjon og kompetanseoverføring

Creates both detailed reference material and concise decision summaries. Adapts depth to executives/managers, controllers, specialists and technical staff. Teaches, facilitates, documents and designs for handover.

### 6.7 Selvledelsesrisiko og mottiltak

Recurring risk: over-expansion, excessive context, repeated refinement and parallel state/documents can reduce speed or bury the strongest signal.

Countermeasures:

- bounded source packets;
- one primary thesis;
- two to four evidence bridges;
- active-state compaction;
- `must resolve` versus `useful to improve`;
- explicit stop/go conditions;
- stop when additional work has no clear decision/selection value.

Do not present this risk in applications unless a question asks about development areas. Use it internally to protect package efficiency.

- **Prosess og forbedring:** prosesskartlegging, standardisering, kontinuerlig forbedring, behovsavklaring, workshop/fasilitering, brukerobservasjon, onboarding, handover og funksjonell endringsforankring.
- **Analyse og styring:** samfunnsøkonomi, sykehusdrift, økonomistyring, budsjettering, DRG, bemanning, gevinstrealisering og beslutningsstøtte.
- **BI og data:** Power BI, DAX, Power Query M, semantiske modeller, stjerneskjema, KPI-er, ETL, datakvalitet og visualisering.
- **Utvikling og automatisering:** Excel/VBA, SQL, R, Python, Git/GitLab, prognoser, modellvalidering og arbeidsflytautomatisering.
- **Leveranse og samhandling:** behovsavklaring, rådgivning, dokumentasjon, workshops/arbeidsmøter, onboarding, kvalitetskontroll og tverrfaglig samarbeid.

Recompose around the vacancy; do not display all clusters automatically. For `ROLE-PROCESS-01`, lead with `Prosess og forbedring` plus the relevant part of `Analyse og styring`; technology follows as an enabler. For direct BI roles, the original BI/data hierarchy may remain optimal.

### 8.2 CV- og dokumentstandarder

- Two A4 pages for the CV unless a shorter/longer format is clearly better.
- Reverse chronology and conventional headings.
- No photo, age, birth date or street address by default.
- Selectable text and simple reading order.
- Calm Scandinavian/editorial hierarchy.
- Warm white, muted navy/blue-gray/petrol, minimal iconography.
- No neon/cyberpunk/startup gloss, robot/brain/circuit imagery, radar charts, decorative skill bars or generic AI imagery.
- Cover page/competence profile only when it adds evidence or positioning, not decoration.

### 8.3 Presentasjonshierarki for KI

1. Business/domain value.
2. Analytical/technical delivery.
3. AI-enabled operating method.
4. Tools.

## 9. Globalt uavklartregister

Omit or retain narrow qualifier:

- exact English portal scale if a standardized label is required;
- whether trust/service or Canadian schooling adds value for a specific CV;
- exact formal scope of any superuser responsibility;
- quantified adoption, time saved, error reduction, cycle-time change, decision impact or AI productivity;
- formal leadership/management authority;
- public-safe portfolio artifacts or externally publishable case materials;
- exact current platform-access scope.

When a material unresolved item determines eligibility or claim strength, ask one targeted question. Otherwise omit it.

## 10. Prioriteringer for sterkere evidens

High-value future additions:

- exact official education/thesis/grade details where desired;
- verified user/adoption and time/error/cycle metrics for selected projects;
- forecast performance by horizon after valid deployment/evaluation;
- formal role/mandate and team/user scope for major projects;
- sanitized project case cards;
- measured before/after evidence for AI-assisted tasks;
- independent calibration of SQL/Python/R depth;
- explicit current superuser system/scope if reusable.

These are future improvements, not blockers for conservative application use.
