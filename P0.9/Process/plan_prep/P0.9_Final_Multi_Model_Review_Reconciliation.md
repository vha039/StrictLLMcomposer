## 0. Executive conclusion

The six-review stack is unusually useful because it spans materially different evidence modes: architecture-author intent, hostile KISS review, direct Windows execution, adversarial state-space exploration, human/model workflow review, and an earlier integrated forensic pass. Once correlation and duplication are removed, the reviews do **not** support a sprawling rewrite. They converge on a much narrower diagnosis:

> **P0.9 is a strong implementation whose core architecture, semantic stage design and most deterministic primitives are sound, but whose integration boundaries do not yet enforce the same currentness, freeze, lineage and provenance guarantees that the individual subsystems appear to provide.**

The principal failure pattern is a distinction between **presence/schema-validity** and **current, correctly bound, eligible state**. The Build often knows enough information to determine currentness, but some public command paths do not require it; some frozen inputs are snapshotted but later bypassed; some current-state records are trusted without revalidating their bindings; some tested helpers are not connected to the production CLI path.

The raw reviewer finding count therefore overstates the number of independent repairs. Most material findings collapse into eight root-cause families:

1. **Frozen-input consumption** — snapshots exist, but schemas/templates and some policy-like inputs are not consumed consistently from the run snapshot.
2. **Semantic binding/currentness** — stage artifacts can be valid but stale-at-birth; context can expose stale work; rendering can bypass semantic currentness.
3. **Render receipt/output coherence** — render reports can be stale yet trusted; old PDFs or mixed human/pipeline formats can remain deceptively current-looking.
4. **Branch lifecycle and transactionality** — parent integrity is underchecked, child rebind is non-topological, and child visibility can precede completed rebinding.
5. **Failure/continuation integration** — failure helpers exist without full production wiring; Stage 3's two-artifact completion is not represented correctly by `next`.
6. **Windows/Word/template reliability** — Word COM is the correct target choice, but MAX_PATH staging, timeout diagnostics/cleanup, render-time template-contract enforcement and forced page layout need targeted work.
7. **Evidence/test/report truthfulness** — 208 passing tests provide real value but overstate integration coverage; Builder/GATE reports claim more than the current artifact proves.
8. **Human/model workflow and pilot readiness** — semantic prompts are strong, while metadata handoff, GATE-10, queue clarity and pilot instrumentation still need bounded preparation.

No reviewer produced evidence that justifies reopening the central P0.9 product architecture: invariant CV+letter, Bokmål-only core, portal exclusion, three manual semantic stages, Stage-3 elasticity, personality ON/0–3, job-local transactions, PDF degradation separation, human irreversible authority, lean evidence indexing, and absence of an LLM quality judge remain well supported.

The correct finalization strategy is consequently:

- **repair shared trust boundaries once, not finding-by-finding;**
- **preserve proven positive deviations;**
- **clarify four narrow architecture semantics where implementation reality exposed ambiguity;**
- **defer product-quality uncertainties to the live smoke/pilot instead of pre-engineering them;**
- **rebuild evidence claims only after public-path adversarial verification.**

## 2. Multivariate convergence: what the stack actually agrees on

### 2.1 Strong consensus backed by direct evidence

Across independent sources, the following are no longer plausible “style disagreements”:

- A frozen run must not use mutable root schemas/templates when evaluating/rendering historical state.
- Rendering must require a **current** semantic chain, not merely a parseable final-package file.
- Render state cannot trust a receipt whose binding/output bytes no longer match current state.
- Semantic upstream bindings must be deterministic/current at artifact acceptance, not merely schema-present.
- Child-run reuse must be topological and transactionally complete before the child is exposed.
- Stage-3 continuation must understand that Stage 3 owns **final + review**.
- The current failure mechanism must be connected to the actual semantic-production path if `FAILED/BLOCKED_MANUAL` is to be meaningful.
- The known forced CV page break should be removed/tuned before measuring semantic quality.
- GATE-10 must be executed against the actual model/surface/privacy workflow before real candidate data is used.

### 2.2 Strong consensus on positive deviations

Independent reviewers repeatedly converged on preserving:

- Word COM as the actual target PDF path;
- targeted repair of the historically corrupt Word masters;
- Calibri retarget based on target font availability;
- semantic package hashing that excludes finalization/date metadata;
- Norwegian-aware `æ/ø/å` filename folding;
- run-local frozen snapshots as the ownership model;
- hash-based no-clobber of human-edited employer artifacts;
- lean factual/mechanical evidence namespaces;
- three semantic stages and strong Stage-3 elasticity;
- PDF degradation remaining orthogonal to semantic triage;
- no portal/language/output-mode branch engine;
- no semantic runtime quality judge or retry orchestration engine.

These are explicit **anti-regression constraints** for the final Codex run.

### 2.3 Where reviewers appeared to disagree but actually exposed different scopes

#### Failure records
The earlier audit proposed wiring the failure record broadly. Pro correctly narrowed this:

- semantic-production submission/recovery failures may own `FAILED/BLOCKED_MANUAL`;
- read-only validation/preflight errors are diagnostics, not necessarily persistent production failure;
- DOCX/PDF conversion/render failures belong to the **render axis**, not production failure state.

The integrated disposition is therefore **FIX the production integration + AMEND/clarify axis ownership**, not “record every CLI error.”

#### `render --dest`
Opus/Gemini correctly observed a literal write-root bypass; Pro correctly identified a legitimate user value in explicit external export. The real invariant is not “humans can never export outside the repository.” It is:

> **canonical pipeline/model-controlled writes remain within approved roots; explicit human export may go elsewhere but must be non-authoritative unless deliberately verified/adopted.**

So the final disposition is **IMPROVE + narrow AMEND clarification**, not blindly delete the feature.

#### Word timeout cleanup
Opus/Gemini identify a plausible orphaned Word process. The earlier audit suggested exact-PID cleanup. Pro correctly warns that complicated process ownership discovery can be riskier than an occasional orphan. The mandatory fix is **truthful diagnostics and safe cleanup behavior**; exact-PID killing is conditional on a proven safe target-Windows mechanism.

#### Personality catalogue
The old PF taxonomy has not been shown to harm the first real packages. Provenance purity alone is insufficient reason to replace it before the pilot. Preserve the current interface through the smoke, but treat its long-term value as **DEFER**, not permanent `KEEP`.

#### GATE-05
The first audit called page balance a high-value improvement; Pro/Luna correctly escalate it to **pre-smoke FIX/required gate completion** because leaving a known forced-break defect would contaminate the product-quality measurement.

## 3. Root-cause model for the final repair pass

The final Codex agent should not receive 50 disconnected tasks. It should solve the following root causes and then close all mapped findings through regression tests.

### RC-1 — Run-local frozen input resolution is incomplete

Symptoms:
- live schema consumption;
- live master consumption;
- live soft-threshold/config interpretation in some paths;
- branch policy-governing comparisons omit shared semantic policy.

Desired invariant:

> Once a run freezes, every content-affecting read for that run resolves through the run's frozen snapshot or an explicitly defined immutable derived record. Root files are maintenance inputs for future runs only.

Best implementation shape: a small **run-local frozen resolver / stage-policy digest**, not a dependency graph.

### RC-2 — Mechanical lineage is model-authored or validated too late

Symptoms:
- Stage 2/3 context omits exact current upstream hashes;
- `stage-submit` can accept wrong semantic upstream hashes;
- accepted artifacts become stale immediately;
- branch reuse can relabel content without rebuilding internal topological bindings.

Desired invariant:

> Semantic models own semantic payload; deterministic tooling owns/verifies mechanical binding metadata. An accepted current artifact is current at birth.

This is the strongest architecture-clarification candidate from the review stack.

### RC-3 — Current semantic eligibility is not a shared action boundary

Symptoms:
- `status` may report STALE while render proceeds;
- finalize/render validate file shape rather than full current chain;
- `context` can prepare a stale downstream handoff.

Desired invariant:

> Any action that consumes a “current” semantic artifact must call one shared readiness/eligibility predicate based on intact run + current upstream binding + artifact validity + required paired artifacts.

No workflow engine is needed.

### RC-4 — Render report is treated as trusted state instead of verified receipt

Symptoms:
- report final hash can differ from current final while status says `OK`;
- output paths may be obsolete;
- output hashes are not rechecked before exposing current render state;
- interruption between file promotion and report writing is awkward to reason about.

Desired invariant:

> A render report is a **receipt**. It is current only when its exact semantic/date/template/config bindings and actual output hashes verify. Unreceipted/mismatched files may exist after interruption but are never current.

This avoids an unnecessary multi-file transaction subsystem.

### RC-5 — Per-component output ownership is incomplete

Symptoms:
- old pipeline PDF may remain after a new degraded render;
- human-edited DOCX can coexist with a newly promoted automated PDF for a different semantic payload;
- ownership knowledge can be lost after transient failure.

Desired invariant:

> A document component's current DOCX/PDF presentation cannot silently split semantic generations. Human-edited files are protected; pipeline-owned stale siblings are removed from current presentation or explicitly classified non-current.

### RC-6 — Branching is not fully preconditioned or topologically transactional

Symptoms:
- compromised parent can produce child side effects before failure;
- tampered parent vacancy can be copied into a child;
- `PENDING` binding patched after child directory becomes visible;
- reused descendants may be labelled current even when upstream must regenerate;
- unchanged branch may immediately derive stale state.

Desired invariant:

> Verify parent completely first; construct/rebind child completely in staging in topological order; validate resulting current chain; expose child atomically once internally consistent.

No event sourcing or manifest-version engine.

### RC-7 — Failure/continuation helpers are not connected to the operator path

Symptoms:
- invalid stage submit does not necessarily create current failure state;
- `BLOCKED_MANUAL`/retry helper is testable but not operationally reached;
- Stage-3 final-without-review is skipped by `next`;
- `next` can operate on compromised runs;
- malformed artifacts can produce raw tracebacks rather than useful current diagnostics.

Desired invariant:

> Disk state alone is enough to continue or diagnose after interruption; public commands create the same state that the tests assert.

### RC-8 — Target-Windows rendering and pilot readiness still have empirical work

Symptoms:
- Word staging paths can cross legacy MAX_PATH around realistic Norwegian names;
- timeout diagnostics overstate process termination;
- render does not enforce template-control preflight at point of use;
- forced CV page break contaminates visual quality;
- GATE-10 remains unexecuted;
- pilot log does not yet exist.

Desired invariant:

> The smoke begins only after target-environment rendering and operator instrumentation are trustworthy enough that observed weaknesses reflect the semantic system rather than known plumbing/layout defects.

## 5. High-value disagreements and final adjudications

### 5.1 Failure recording: wire it, but narrowly

**Rejected extreme:** persist every validator/render/preflight failure into production `FAILED`.  
**Adopted interpretation:** persistent current failure records represent failed **semantic-production attempts/recovery** and exhausted/manual block. Render conversion belongs to render state; read-only validation is diagnostic unless it corresponds to a current attempted artifact. This preserves the three-axis architecture.

### 5.2 External export: distinguish authority from convenience

**Rejected extreme A:** arbitrary `--dest` is harmless because a human requested it.  
**Rejected extreme B:** any write outside run/generated roots must be deleted.  
**Adopted interpretation:** canonical pipeline output remains protected/in-repo; explicit human export can be supported as a convenience, but exported bytes do not become current state simply by being written. An explicit verified adoption mechanism may exist only if it remains small and useful.

### 5.3 Render atomicity: receipts beat multi-file transactions

A normal filesystem cannot atomically commit two DOCX, two PDF and a JSON report as one transaction. Building a transaction coordinator would be an architectural regression. The correct property is **detectable currentness**: exact receipt bindings + output hashes mean interrupted/unreceipted files are harmless and rerunnable.

### 5.4 Branch reuse: topological rebind is required; a lineage engine is not

Gemini's proposed “topological hash propagation” is substantively correct, but it does not require a new architecture mechanism. It is the minimal implementation of the existing child-reuse rule. Child artifacts are rebound in strategy→draft→final→review order only when each predecessor is current under child inputs.

## 8. Architecture clarifications worth carrying forward

The implementation evidence supports **four narrow clarification amendments**, all proposed principally by Sol Pro. These improve future interpretability without changing product architecture.

### AMEND-1 — Deterministic binding envelope ownership

**Clarify:** semantic models author semantic payload; deterministic tooling stamps/verifies run/job/current-upstream/policy binding metadata. Models may see bindings for context but are not responsible for manually reproducing canonical hashes correctly.

**Why:** current implementation repeatedly creates stale-at-birth risk and human/model friction by making model artifacts carry deterministic metadata without complete handoff support.

### AMEND-2 — Render reports are verified receipts

**Clarify:** render report currentness derives from exact semantic/date/template/config bindings and output hashes. Output files can exist without a current receipt after interruption; such files are non-current, not transaction corruption.

**Why:** avoids impossible multi-file atomic transaction semantics while making interrupted work fully detectable/rerunnable.

### AMEND-3 — Failure-record axis ownership

**Clarify:** current `FAILED/BLOCKED_MANUAL` represents semantic-production attempt/recovery state. Read-only validation/preflight diagnostics do not automatically become current production failure, and DOCX/PDF/render failures stay on render axis.

**Why:** prevents a literal implementation of broad `CTR-03` wording from collapsing the architecture's orthogonal states.

### AMEND-4 — Explicit human external export

**Clarify:** deterministic/model-controlled canonical writes remain inside approved roots. A deliberately human-requested export may target an external path, but it is non-authoritative unless explicitly verified/adopted.

**Why:** preserves useful no-clobber/export ergonomics without weakening control-plane write boundaries.

## 10. High-value adversarial tests for the perfection pass

The goal is not a higher test count. These tests should prove entire invariants through public paths.

1. **Frozen-root metamorphism:** freeze run; change root schema/template/policy/settings/personality/authority/index source one at a time; old run validation/context/render must remain governed by frozen bytes.
2. **Frozen self-tamper:** mutate the run's own frozen byte; every mutating/current-work command refuses, while status gives a clean integrity diagnosis.
3. **Current-at-birth:** submit Stage 2/3 artifacts through public command with intentionally wrong current-upstream hash; command rejects before persistence.
4. **Stale action refusal:** replace strategy/draft/final to create stale descendants; `context`, `finalize` and `render` cannot treat stale descendant as current.
5. **Render receipt metamorphism:** alter final/date/output byte after render; status immediately ceases to report current render OK.
6. **Interrupted render receipt:** leave promoted files without receipt or receipt without matching file; current state is non-current and rerender is safe/idempotent.
7. **Degraded rerender:** new DOCX + PDF failure after prior valid render; old pipeline PDF cannot remain visually/currently authoritative.
8. **Human DOCX collision:** human edit DOCX, rerender; DOCX protected and corresponding automated PDF does not advance to a different semantic generation.
9. **Parent-compromise branch:** tamper parent frozen authority or vacancy; branch produces no child side effect.
10. **Identical child branch:** complete valid parent → branch unchanged → child final/review remain current after correct topological rebind.
11. **Changed-policy child:** alter content-governing stage/shared policy → correct earliest semantic artifact regenerates and descendants are prior context, not current.
12. **Branch interruption:** simulate crash before final rename; no canonical partial child. Simulate after rename only if all child state was already complete.
13. **Stage-3 interruption:** final current + review missing/invalid → `next --stage 3` selects same job and context requests only remaining/current work.
14. **Malformed artifact:** invalid JSON/non-object in current artifact → clean diagnostic/FAILED behavior, no traceback.
15. **Failure lifecycle:** invalid real `stage-submit` creates appropriate current semantic failure; corrected successful submission clears/supersedes it; render failure does not create semantic production failure.
16. **Exception isolation:** core stage-submit/finalize behavior for EXCEPTION cannot accidentally create a second core workflow.
17. **Word long-path:** realistic worst-case employer/title on actual repository depth converts successfully due short staging path while final human filename remains readable.
18. **Template mutation/control:** unknown/duplicate/missing SDT in frozen master fails render locally before employer document generation.
19. **Private-ID leakage:** `EMP-...` / `EDU-...` rejected; ordinary employer language remains unaffected.
20. **Evidence honesty:** traceability maps each critical invariant to at least one test that invokes the public production path, not merely a helper name.
