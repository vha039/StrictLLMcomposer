# Optimal Model×Effort Configuration for the Jobbsøk_26 Two-Stage Semantic Pipeline

## TL;DR
- The placeholder names in the brief are **real, currently-available OpenAI models**: `SOL_CLASS → GPT-5.6 Sol` and `TERRA_CLASS → GPT-5.6 Terra` map to genuine GPT-5.6-family models (GA July 9, 2026); the frozen single-slot default `stage1 = stage3 = GPT-5.6 Sol` is a defensible baseline but is **not** quality-optimal once per-stage flexibility exists.
- **Best all-round configuration:** put a schema-disciplined, high-effort auditor in Stage 1 and a restrained-prose model at *medium* effort in Stage 3 — the winning daily-driver pairing is **GPT-5.6 Terra · high → GPT-5.6 Sol · medium** (or the cross-vendor **GPT-5.6 Terra · high → Claude Sonnet 5 · medium** if you accept a second data-posture review), because Stage 1's zero-prose JSON output lets a cheaper model run at high effort with no penalty, while Stage 3 prose degrades above medium effort.
- **Two hard constraints dominate the exotic options:** (1) high/xhigh effort actively *hurts* Stage 3 (the inverted-U / *kansellistil* risk is real and documented), so never run Stage 3 above medium; (2) Claude's best-prose model (Fable 5.1) is a "Covered Model" with **mandatory 30-day retention and no ZDR**, disqualifying it as a default for a pipeline processing a real person's psychometric and career data.

## Key Findings

1. **§1 name-verification (explicit operator request).** GPT-5.6 Sol, GPT-5.6 Terra, and GPT-5.6 Luna are confirmed real OpenAI models, previewed June 2026 and generally available July 9, 2026 across ChatGPT, Codex, and the API. The operator's 2026-08-28 mapping stands. Note that OpenAI shipped a *newer* flagship after the gate record was written — **GPT-6 Astra** (September 3, 2026) — which the brief's ground truth does not mention; it is a legitimate Stage-1 candidate but is on a gated/staged rollout ("Daybreak" access first).

2. **Effort is stage-asymmetric.** Stage 1 writes only schema-bound JSON, so it is immune to the prose over-reasoning penalty and can safely run at **high/xhigh** — more audit reasoning, no stylistic cost. Stage 3 authors restrained Bokmål prose, where multiple independent sources document that longer reasoning traces "clutter or disrupt" holistic prose judgement (the inverted-U), and practitioners find **medium beats high** for text-shaped work. This single asymmetry drives every ranking.

3. **The retry economy rewards decoding-level schema guarantees, not ceiling IQ.** OpenAI Structured Outputs (strict mode) enforces validity at the token-generation layer — OpenAI reports gpt-4o-2024-08-06 "achieves 100% reliability in our evals, perfectly matching the output schemas," versus under 40% for the older gpt-4-0613 on the same complex-schema eval; Gemini enforces response schemas natively, while Claude enforces via tool_use — highly reliable but not *guaranteed*, and recursive/complex schemas are rejected outright by all constrained-decoding vendors. Because Jobbsøk_26 gives each job only a bounded correction/re-attempt budget before `BLOCKED_MANUAL`, a model that emits malformed JSON burns that budget regardless of its analytical ceiling. This favors GPT for Stage 1 specifically.

4. **Cross-vendor pairing is nearly free here.** The two stages run in fully separate sessions and communicate only through a schema-validated JSON file on disk. There is no shared conversational state to corrupt, so the usual cross-vendor "consistency tax" collapses to an operational cost (a second API account and a second `GATE-10` data-posture review) — not a quality cost.

5. **Data posture is a first-class quality axis, and it splits the vendors.** OpenAI offers ZDR for frontier models with no training by default. Anthropic's commercial API never trains on customer content and offers ZDR on request — **except** Fable 5 / Fable 5.1 / Mythos, which are "Covered Models" requiring 30-day retention with no ZDR opt-out (effective June 9, 2026). Google's *paid* Gemini API and Vertex AI contractually exclude training (the "Training Restriction" in Google's Service Specific Terms) and support a genuine ZDR path on Vertex (disable in-memory caching, which otherwise has a 24-hour TTL, plus an abuse-log exception), but the *free* AI Studio tier trains on input and human reviewers may read it — Google explicitly warns "Do not submit sensitive, confidential, or personal information to the Unpaid Services."

6. **Long-session drift is partially — not fully — mitigated.** The pipeline's between-jobs "re-derive all state from disk" step functions like the single-turn anchor that the ContextEcho persona-drift benchmark found restores a model's deployed register; but the same research shows in-session compaction does *not* reliably reset drift and that neither reasoning tier nor vendor predicts drift magnitude. With the current N=2 batch this is moot; at larger batches it is an unquantified risk.

### Prose-quality evidence (Stage 3 relevant)
Blind and practitioner evaluations consistently rank Claude highest for natural, restrained, tone-consistent prose and non-English nuance. In Lokalise's 2025 blind study, professional translators rated 78% of Claude translations "good" — higher than GPT-4, DeepL, or Google Translate — and at WMT24 Claude 3.5 ranked first in 9 of 11 language pairs evaluated. GPT-5.x is rated strong-but-slightly-flatter and best for *structured/templated* output; Gemini is rated "functional but flat." On the "Be My Cheese?" cultural-nuance translation benchmark (arXiv 2602.04729; 7 models, 15 target languages, 5 native-speaker raters each), the strongest tier was statistically indistinguishable — GPT-5 (2,10/3), Claude Sonnet 3.7 (1,97/3), and Mistral Medium 3.1 (1,84/3) — all well ahead of open models. **No frontier-model Bokmål prose benchmark exists** — NorEval (Mikhailov et al., Findings of ACL 2025) benchmarked 19 open-source LMs across 24 human-created datasets covering both Bokmål and Nynorsk, but covers only smaller Norwegian-specific open models, not the frontier commercial models evaluated here. This is the single largest evidence gap in the whole exercise.

### Instruction-following / schema evidence (Stage 1 relevant)
A widely-cited Codex GitHub issue (#36538) reports GPT-5.6 Sol as a "serious product regression" versus GPT-5.5 for careful instruction-following — it "forgets important instructions," "needs repeated reminders," and "tries multiple indirect approaches instead of following the clear correct approach." Because Stage 1 is a forensic, instruction-dense audit under a strict schema, this is directly load-bearing and is why GPT-5.5·high and GPT-6 Astra·high are credible Stage-1 alternatives to Sol despite Sol being newer.

## Recommendations

**Stage 0 — before you trust any of this (now, N=2 batch).** Write the first rows of `PILOT_LOG.csv`. Run the same 2 CORE jobs through three configurations back-to-back: (a) the frozen default **Sol·medium → Sol·medium**; (b) the daily-driver **Terra·high → Sol·medium**; (c) a Claude-prose Stage-3 variant **Terra·high → Sonnet 5·medium**. Score `overall_quality_score`, `known_factual_corrections`, and `retry_or_rerun_result`. This single experiment resolves the two load-bearing unknowns (Terra-vs-Sol audit delta; Claude-vs-GPT Bokmål prose delta) that every table's confidence hinges on.

**Stage 1 — adopt as default (daily driver).** **GPT-5.6 Terra · high → GPT-5.6 Sol · medium**, all-OpenAI, single ZDR/`GATE-10` review. Rationale: captures the free-lunch interaction (high-effort cheap auditor + medium-effort quality writer), best data posture, lowest operational overhead. **Never set Stage 3 above medium.**

**Stage 2 — escalate only on evidence.** If pilot logs show Sol·medium prose is measurably flat in Bokmål, switch Stage 3 to **Claude Sonnet 5 · medium** (best value) or **Opus 5 · medium** (ceiling), accepting a second posture review. If pilot logs show Terra·high misses audit nuance on hard postings, promote Stage 1 to **Sol·high** or **GPT-6 Astra·high**.

**Budget mode.** Use **GPT-5.6 Terra · medium → Claude Haiku 4.5 · medium** (or all-Terra for one posture review). Avoid dropping Stage 1 to Luna unless a pilot confirms Luna·high holds the zero-hallucination floor on Norwegian audits.

**Data-posture gate (mandatory).** Do **not** use Claude **Fable 5.1 / Mythos** (Covered Models, no ZDR) or any **free Gemini AI Studio** tier for this pipeline — both retain/train on the exact class of sensitive personal data this system processes. If using Gemini at all, use **Vertex AI with in-memory caching disabled + abuse-log ZDR exception**. Confirm OpenAI ZDR is active on the account before first production run.

**Thresholds that change the recommendation.** (1) If batch size grows past ~15–20 sequential jobs in one session, re-test for drift and consider forcing a hard session restart between jobs (the ContextEcho anchor evidence suggests disk-re-grounding helps but does not fully reset). (2) If GPT-6 Astra's price falls toward Sol's, it becomes the default Stage-1 auditor. (3) If a credible Bokmål prose benchmark publishes and favors Claude decisively, make Claude the default Stage-3 writer.

## Caveats
- **Zero empirical calibration.** Every score is a pre-registered prior; `PILOT_LOG.csv` is empty. Sub-scores are my structured judgement against the §3 rubric, not measurements. Treat ranks within ~0,3 points as ties.
- **The largest evidence gap is Bokmål prose quality of frontier models** — no public benchmark exists; the Claude-prose premium is inferred from English/multilingual and blind-writing evidence (Lokalise 2025, WMT24, "Be My Cheese?").
