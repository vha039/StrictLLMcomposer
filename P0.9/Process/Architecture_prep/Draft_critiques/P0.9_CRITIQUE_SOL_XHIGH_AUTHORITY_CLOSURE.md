# P0.9 — Sol XHigh Authority & Architecture-Closure Critique

### 1. Executive verdict

**Verdict: the draft is materially strong as a candidate, but it is not authority-closed and must not be frozen as written.** I find **4 P0 freeze blockers, 11 P1 major defects, and 8 P2 significant defects**. The defects are concentrated rather than diffuse: the three-stage topology, final-writer elasticity, human clustering, job-centric/derived-state direction, partial-success doctrine, and deletion of genuine obsolete portal/cluster-plan machinery are broadly sound. The architecture fails closure mainly where it converts missing evidence into policy, deletes authoritative channel facts together with portal machinery, weakens its own immutable-run model, and lets verification or acceptance rules change the product contract.

The most important authority result is this: **the draft is allowed to choose among user-permitted Step-1 options, but it may not pretend that a prerequisite explicitly assigned to Step 1 has already been satisfied.** The context package makes the first-batch vacancy/channel inventory blocking for `RQ-01`, `RQ-02`, and `RQ-14`; the draft instead freezes invariant CV+letter, portal detachment, and Bokmål-only first, then moves the inventory into a `STEP2_VERIFY` gate. That is precisely the false-closure pattern the audit brief asks to detect.

Four issues block adoption as a final P0.9 normative architecture:

1. **`DEC-01/02/03/04` are frozen before their canonical Step-1 inventory prerequisite exists.** The draft itself sequences “freeze architecture → complete vacancy inventory,” contrary to the canonical resolution queue.
2. **Portal-generation machinery is correctly removable, but the draft also deletes the vacancy/channel fact model.** That contradicts the locked status of vacancy channel facts and the evidence file's explicit conclusion that channel facts remain necessary even with a detached portal workflow.
3. **The “one immutable run authority” contract is undermined by `freeze --amend`, which can update hashes under the same run while old artifacts survive without binding themselves to the manifest version/hash that produced them.** This is not auditable immutability.
4. **`GATE-03` allows DOCX-only delivery if PDF conversion fails, while `CTR-01`, `ACC-17`, the finalizer, and derived status define all four DOCX/PDF files as required.** A verification fallback may not silently weaken a frozen product contract.

The next-highest-risk defects are: arbitrary exception thresholds that also disagree across the three drafts; exception handling that can improve `Q_happy` mechanically by removing up to a material share of approved jobs from its denominator; a failure-state design that cannot actually derive `*_FAILED` without reading history; an impossible hard invariant against cross-job semantic carryover inside one sequential cluster chat; false use of `DERIVED_LOSSLESS_VIEW`; factual-authority leakage through `CV_BASELINE` entries in the evidence index; hard requirement/cardinality limits with no authority basis; and acceptance criteria that reward a desired Stage-3 behavior instead of measuring it.

No web research was necessary. These are authority, internal-consistency, and contract defects settled by the supplied seven-file evidence base.

#### SOL-004

- **Severity:** `P0` freeze blocker
- **Exact draft location:** Decision Record `L67-L75`; Normative Spec `L282-L304, L355-L386, L393-L414`; Implementation Contract `L39, L55, L74, L152, L193`.
- **Canonical context evidence:** `01_CURRENT_STATE_AUTHORITY_AND_DECISIONS.md:L98, L113-L118, L133-L135`; `00_READ_THIS_FIRST.md:L37-L40`; `04_IMPLEMENTATION_BASELINE_AND_BUILD.md:L442-L455`.
- **Defect:** The draft calls `run_manifest.json` **one immutable frozen run authority**, then allows `freeze --amend` to write a new manifest version, update hashes, and retain existing job artifacts unless “their own inputs changed.” The stage artifacts do not carry the manifest version/hash under which they were produced. Worse, candidate factual authorities are user-locked as immutable during a production run, but §7.6 explicitly allows “hashes updated” under the same run. This is versioned mutation of the authority while preserving artifacts whose provenance may point to the previous authority.
- **Real consequence:** After amendment, one `run_id` may contain current artifacts produced under different manifest/policy/source snapshots, while status reads only the latest manifest and deliberately ignores history. Candidate-authority changes should not be accepted as an in-run amendment.

### 6. Findings investigated and rejected as non-issues

1. **Selecting a user-permitted option is not itself an authority violation.** Step 1 exists to select among open choices. The defect in `DEC-01/02/04` is the ignored prerequisite and over-deletion of channel facts, not the mere act of choosing a permitted simplification.
2. **The three-stage `SOL_CLASS → TERRA_CLASS → SOL_CLASS` topology is properly inherited/ratified.** No later user decision supersedes it, and the draft preserves the explicit `ELASTIC` final-writer rule. No fourth judge/planner stage is needed for closure.
3. **`strategy.json` does not become mechanically binding on the final writer merely because it is structured.** The spec explicitly prohibits final-vs-strategy semantic comparison, uses vacancy/source-first Stage-3 read order, and allows full reconstruction. The concern is anchoring and arbitrary schema bounds, not a hidden hard lock.
4. **The draft generally respects the mechanical/semantic validation boundary.** It explicitly says reference resolution does not prove support, schemas do not prove factual truth, and writing-quality checks stay outside deterministic validation. SOL-009 is a local acceptance/test mismatch, not a wholesale semantic-validator failure.
5. **Deleting P0.8.1 portal-answer hardening is correct if portal generation is detached.** Duplicate question IDs, portal-answer arrays, and portal delivery classes should not survive as zombie core contracts. The patch is to retain **channel facts**, not to resurrect the old portal package model.
6. **Deleting model-generated `cluster_plan.json` and Priority A/B treatment is coherent.** No surviving consumer justifies them, and differentiated treatment would confound the pilot. Human priority/order remains available.
7. **The evidence index need not prove retrieval gain to be adopted for provenance/addressing.** The draft correctly separates `EXP-05` retrieval value from the enforcement/addressing rationale. The defect is source-role leakage and overclaiming what a resolved ref proves.
8. **Per-document LibreOffice invocation is correctly framed as a safe implementation posture, not a permanent empirical fact.** `GATE-04` can permit one invocation for both documents without changing the render transaction invariant.
9. **P0.7's non-data-bound SDT fill→unwrap technique is not rejected from generic folklore.** The draft correctly preserves reuse-after-inspection and target-machine testing.
10. **Page count is not used as a semantic truth/quality gate.** The draft appropriately keeps sparse/normal/dense page behavior as usability/editorial guidance and hard-fails only unusable output or explicit external limits. The separate channel-fact defect prevents the latter from working reliably and must be patched.
11. **No stale P0.8/P0.8.1 cluster/progress/portal contract zombie was found after the corresponding surface was explicitly deleted.** The notable stale inheritance is instead the P0.7 schema-cardinality set in SOL-011.
12. **Luna/preparation is correctly absent from the baseline and kept causal/optional.** No baseline dependency or factual-authority role leaks in from that experiment.
